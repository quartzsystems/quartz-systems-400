# The ILE RPG compiler

`CRTRPGMOD`, `CRTBNDRPG` and `CRTSQLRPGI` compile ILE RPG source to the
IR of Phase 4 (`QIR.md`); the IR is verified, generated by Cranelift and
bound like any other module. This document describes the compiler as
built; `PHASE9.md` has the oracle method, the corpus status and what is
deferred.

## Crates

| Crate | Folder | What it does |
|---|---|---|
| `rpgspecs` | `rpg/specs` | The column layouts of every specification form (`specs/rpgle.toml`), shared with SEU's format lines and prompts |
| `rpgfront` | `rpg/front` | Source reading, directives, `/COPY`, the fixed-form cutters, the free-form lexer, the parser, the syntax tree |
| `rpgc` | `rpg/compiler` | Control options, declarations and layouts, files, checking and IR generation, the listing, the message texts |
| `qrpgrt` | `rpg/qrpgrt` | The runtime library: bound procedures `_QRNX_...` generated code calls |
| `rpgsqlpre` | `rpg/sqlpre` | The SQL precompiler of `CRTSQLRPGI`: embedded statements, host variables, the precompile listing |
| `rpg-oracle` | `tools/rpg-oracle` | The differential oracle (`PHASE9.md`) |

The conformance kit is `tools/conformance/src/rpg/` with the test
`tools/conformance/tests/rpg_kit.rs`.

## Front end

**Reading** (`reader.rs`). The main member and every `/COPY` and
`/INCLUDE` it reaches are read in order into lines, each numbered as
the listing numbers it (copied lines get their own numbers) and
classified: a fixed-form specification (its letter, upper or lower
case), free-form text, a comment, a directive, the `**FREE` marker,
a `**CTDATA`/`**FTRANS`/`**ALTSEQ` header, compile-time data, an
embedded SQL line (`C/EXEC SQL`, `C+`, `C/END-EXEC`), or a line
conditional compilation skipped. A member whose first record is
`**FREE` is fully free (the whole line is free form); elsewhere a line
with columns 6 and 7 blank is free form in columns 8 to 80, and
columns 81 to 100 are comments. Directives start with `/` in column 7
(or, in free form, as the first non-blank). `/COPY` nests to
`COPYNEST` (32); a member already on the copy stack is refused
(`RNF0024`), a missing one is `RNF0273`. `/DEFINE`, `/UNDEFINE`, `/IF
[NOT] DEFINED`, `/ELSEIF`, `/ELSE`, `/ENDIF` and `/EOF` follow IBM's
rules; an `/IF` open at the end of its member is an error.

**Predefined conditions.** Every compile defines `*ILERPG`, the
command's own (`*CRTBNDRPG`, `*CRTRPGMOD`) and one name for each IBM
release up to the one QS/400 claims: **V1R0M0 is V7R5M0** for target
release and conditional compilation, so `*V4R4M0` through `*V7R5M0`
are defined (`rpgc::RELEASES`). Code guarded by `/IF DEFINED(*V7R3M0)`
compiles; code guarded by a later release does not.

**Lexing** (`lex.rs`). Free-form statements, keyword areas and
fixed-form factors share one tokenizer. A `*` right after an operand
multiplies; one after a blank or no operand, before a letter or digit,
starts a special word (`*INLR`, `*BLANKS`, `*IN(5)`). Prefixed literals
are `X' G' U' D' T' Z'`; `*ALL'x'`, `*ALLX'..'`, `*ALLG'..'` are single
tokens. A literal open at the end of a line continues when its last
non-blank character is `+` (resume at the next line's first non-blank)
or `-` (resume at the first column of the area); otherwise it is
`RNF0267`. `//` starts a comment outside literals.

**Items** (`parse/mod.rs`). A fixed-form specification and its
continuation lines are one item: `F` and `D`/`P` keyword lines (columns
7 to 43 blank), a `D`/`P` name ending in `...`, a `C` operation's
extended factor 2 (columns 7 to 35 blank), `I` and `O` field lines and
`AND`/`OR` lines (a record line may leave the file name blank; it has
its sequence or type). `C` lines that hold only conditioning belong to
the operation after them. A run of free-form lines is tokenized at once
and cut at semicolons; **one statement per line**: anything after a
statement's semicolon on its line is `RNF5508` and is dropped, as IBM's
compiler does. A statement without a semicolon at the end of its run is
`RNF5507`.

**Parsing.** Both forms give the same tree (`ast.rs`): a definition
keeps its `D`-spec columns (`DefCols`) or its free-form type keyword
among its keywords, and the analysis reads either; every calculation is
an `Op` with IBM's operand roles (factor 1, factor 2, result, extended
factor 2), free-form operands assigned to them by operation
(`parse/ops.rs`). An assignment is an implicit `EVAL`, a bare call an
implicit `CALLP`. Expressions follow IBM's precedence: `()`, calls and
built-ins, unary `+ - NOT`, `**` (right to left), `* /`, binary `+ -`,
the comparisons, `AND`, `OR`. A numeric entry of a fixed-form column
that does not end in the column's last position is `RNF0263`
(severity 20, taken as right-adjusted).

## Declarations

`rpgc::decl` turns definitions into symbols (`syms.rs`) with IBM's
storage sizes (`types.rs`): `P` `digits/2+1`, `S` digits, `B` 2, 4 or 8
by digits, `I`/`U` 1, 2, 4, 8 bytes for 3, 5, 10, 20 digits, `F` 4 or
8, dates by format, timestamps 19 or `20+p`, pointers 16. A fixed-form
type column left blank is packed for a standalone field with decimals,
zoned for a subfield with decimals, character otherwise.

A data structure is laid out in declaration order: absolute positions
(`from`/`to`, `POS`) where given, `OVERLAY(name[:pos|*NEXT])` relative
to the named subfield, length notation at the next position, pointers
rounded up to 16; the length is the larger of `LEN`/the `DS` line and
the end of the last subfield. A structure without subfields is
`RNF3530` (information). `LIKEDS` copies the layout and qualifies the
copy.

In the IR a data structure is a named struct type
`DS_NAME = struct(len) { all_: char(len) @0, SUB: T @off, ... }`: the
hidden field `all_` is the structure as character data (assignments
of character values, `%CHAR`, output), the subfields are its other
fields, overlays overlap. `*IN01`-`*IN99` are one struct (`$in`) of an
`all_` and an indicator array; the other indicators are statics of
their own.

## Generation

One walk over each procedure's calculations checks and generates them
(`codegen/`): `expr.rs` evaluates expressions into IR operands of known
RPG types, `stmt.rs` the operations and the structured groups,
`bif.rs` the built-in functions and calls, `output.rs` the output
specifications. Every procedure is IR text built by `emit::Body`
(blocks, terminators, temporaries); an instruction after a terminator
opens a new block, so code after `LEAVE` stays valid IR.

**Numbers.** Decimal arithmetic states its intermediate precision with
`qdecimal::arith::intermediate` (`DECIMAL.md` §4), the floor being the
assignment target's decimal positions (one more under `(H)`); integer
operands (other than `/`) use integer arithmetic with overflow
checking; a float operand, or `**`, makes the operation float.
`%ABS` of an integer is unsigned, and unsigned operands, alone or with
literal integers that are not negative, use unsigned arithmetic: a
negative result is status 103 (`%ABS(I) - 478` with `I = -32`, and
`895 - %ABS(I)` unmonitored ends the program with `CEE9901`). An
`EVAL` that overflows its target is status 103 (`MCH1210`); the
fixed-form arithmetic operations (`ADD`, `SUB`, `MULT`, `DIV`, `Z-ADD`,
`Z-SUB`) drop high-order digits instead (`dec.mov ... trunc`). RPG
writes the positive sign `F` in packed and zoned data, so an `RPGLE`
module's decimal stores do (`ABI.md`, the descriptor's bit 56).

**`RNF7551`** (decimals lost to the 63- or 30-digit limit) is given
for an operation whose intermediate keeps fewer decimals than it wants:
assigned, the smaller of the floor and the operation's own (a
product's sum, a sum's larger; a quotient has none, so only the floor
counts); compared, only an operation with an operand that is a
quotient, or was computed from one, wants its own decimals. It is
reported on the line of the operation's right operand as the parser
holds it: its operator when it is itself an operation, its first token
otherwise. So `(V6 + 289) - (V2 /` with `2)`
on the next line is reported on the first line (the `/`), and
`(140.22 / 1) -` with `143.96)` on the next on the second; two in one
statement on different lines are two messages.

**Undefined names.** `RNF7030` once per name, at its first reference;
`RNF7503` once per statement that references one, at the reference.

**The cycle.** A cycle-main module's entry procedure runs IBM's cycle:
initialization (the globals' initial values, the files opened, `1P`
on), then per cycle: heading and detail output, total calculations
(those with `LR` or another level in columns 7-8, run while `LR` is
on) and total output, the end when `LR` is on (files closed, the
program re-initialized on its next call), the detail calculations, and
a return without ending when `RT` is on. `RETURN` ends the program when
`LR` is on and returns leaving it active otherwise. Subroutines are
blocks with a return-point slot each and one `switch` at `ENDSR`.

**The cycle with a primary file** (`codegen/cycle.rs`) follows IBM's
order: heading and detail output; `1P`, `MR`, `L1`-`L9` and the record
identifying indicators off; unless `LR` is already on, the next record
read from the file the last one came from (every primary and secondary
file on the first cycle, each into its own buffer); record selection:
with matching fields (`M1`-`M9`) the lowest value, the earlier file on
a tie, otherwise the primary to its end and then each secondary; at the
end of every file `LR` and `L1`-`L9` on; for the selected record its
record type (identification codes) and identifying indicator, the
control break (the highest level whose fields changed is set on with
every level below it, all of them on the first record) and `MR` (another
file holds or last gave a record with the same matching value); total
calculations, a run of each level under its indicator, and total output
(not on the first cycle); the end when `LR` is on; overflow output
(heading and detail records conditioned by an overflow indicator that
is on, then the indicator off); the selected record's fields and field
indicators; detail calculations. An output record with fetch overflow
(`F`) runs the overflow output first when the indicator is on.

**Files** (`extfiles.rs`, `codegen/dbio.rs`). The compiler reads an
externally described file's formats through `rpgc::ExtFiles` (names,
types, buffer offsets, keys, level identifiers, which the IR file
declaration carries for the level check at open). Each format kept by
`IGNORE`/`INCLUDE` is a symbol under its `RENAME` name and its fields
become program fields named with `PREFIX` and the I-spec renames,
unless the file is `QUALIFIED`; a field of the same name in two files
is one field, and an `EXTNAME` subfield of that name takes it over.
`EXTNAME(file[:fmt][:*ALL|*INPUT|*OUTPUT|*KEY])` and
`LIKEREC(fmt|file.fmt[:type])` structures take the format's fields as
subfields (`*ALL` at their buffer offsets, the others packed in order,
`*KEY` in key order). Program-described input fields get their types
from the I specs (`P B I U F`, zoned with decimals, character
otherwise), and a fixed-form result field with a length is defined by
its calculation (packed with decimals, character without).

Every disk file has a record buffer. A read into the buffer moves the
format's fields into the program's (program-described: the record type
from the identification codes, its indicator, the fields and their
field indicators); `WRITE`/`UPDATE` move them back first (`UPDATE
%FIELDS` only the named ones); a result structure is read or written
instead of the buffer. A key is built in record layout from a value,
`(a:b)`, `%KDS(ds:n)` or a `KLIST`; a file without keys positions by
relative record number; `*START`, `*END`, `*LOVAL`, `*HIVAL` are the
IR's limits. After an operation `dbfb` gives `%EOF` (reads), `%FOUND`
(`CHAIN`, `SETLL`, `SETGT`, `DELETE` with a key), `%EQUAL` (`SETLL`) for
the file and for the last operation of the kind; a status of 1000 or
more is an error: `(E)` or an error indicator sets `%ERROR` and
`%STATUS` (the file's and the last), and the resulting indicators are
set as IBM's columns say. `DELETE` with a key chains first. `OPEN` of an
open file is 01215; `CLOSE` of a closed one does nothing; `CLOSE *ALL`
closes every global file. Program-described output records to a disk
file are built at their end positions (data format `P`/`B` packs) and
added (`ADD`, or any output file), updated or deleted (`DEL`).

**File exceptions** (`codegen/dbio.rs`, `qrpgrt::exc::file_err`). An
error status with neither `(E)` nor an error indicator stores the
file's number in `$ferr` and sends the escape `RNXnnnn` of its status
(`RNX1221`, `RNX1021`, ...) to the running entry; the runtime gives it
that status, so `ON-ERROR 1221`, `*FILE` and `*ALL` take it and
`*PROGRAM` does not. An explicit `OPEN` that fails is 01217, a file the
program opens itself 01216 (RPG's `db_open` returns the status, it
sends no `CPF` escape). With no `MONITOR` the cycle's region takes it:
in a cycle-main module with a `*PSSR` or an `INFSR` the cycle is one
`monitor` region whose `*PROGRAM` handler runs `*PSSR` and whose `*FILE`
handler runs the `INFSR` of the file `$ferr` names (`INFSR(*PSSR)`
too); a file without one, or no region at all, leaves it unhandled, so
the function check and the inquiry end the program with `CEE9901` at
the caller: `*PSSR` never sees a file error of a file without `INFSR`,
and the region passes the function check `CPF9999` on unhandled. The
handler's `ENDSR` return point decides the rest: `*GETIN` and `*DETC`
(and the other cycle points) go back to the cycle's top, `RETURN` ends
as `LR` says, blank or `*CANCL` hand the exception on. A file error
leaves the PSDS status as it was (the exception identifier is still
noted at 40); `%STATUS` is the file's, and an operation on a closed
file puts 01211 in the INFDS from the generated code (the runtime knows
the INFDS only while the file is open). A program-described printer's
`WRITE` sets `%STATUS` to 0. In a subprocedure the escape
percolates: the caller's `MONITOR` sees 00202. A subroutine is a
procedure of its own: its body is one region whose handler returns
`exc::rp::FAILED`, and the `EXSR` sends the exception again, so the
main procedure's handlers see the status itself, not 00202.

**Display files** (`codegen/dspio.rs`). A `WORKSTN` file is externally
described from its `*FILE` display object (`dspf`): `rpgc::ExtFiles`
gives each record format its named fields and both buffers' layouts
(`DspLayout`: the output buffer's option indicators and fields, the
input buffer's response indicators and fields, a subfile record's
input holding its output fields too) and the file's `INDARA`. The
formats and fields are declared as for database files. The file has
one record buffer: an output (`WRITE`, `EXFMT`, `UPDATE`) moves the
format's shown fields and option indicators into it, an input (`READ`,
`EXFMT`, `CHAIN`, `READC`) moves the fields read and the response
indicators back. Indicators are `*IN01`-`*IN99`, or the `INDDS`
structure's positions; with `INDARA` the area (`INDDS`, or `*IN`)
goes with the operation as `dspio ... inds()`, and the listing notes
`RNF7089`. `EXFMT` writes then reads; `WRITE` of a subfile record puts
it at its `SFILE(fmt:field)` number; `CHAIN n fmt` reads one (`%FOUND`,
the not-found indicator); `READC` the next changed one (`%EOF`, the
number into the `SFILE` field); `UPDATE` replaces the record last read.
A `READ` by file name reads the format last written that takes input,
and its fields move by the format name the information data structure
names (the program's `INFDS`, or a hidden one). After a read the
attention identifier (`dbfb` bits 8-15) sets `*INKA`-`*INKY` for F1 to
F24, all others off. The `INFDS` has IBM's display part (the attention
identifier at 369, the cursor at 370-371). `OPEN`, `CLOSE`, `USROPN`,
`%OPEN` and `%STATUS` work as for database files (`OPEN` of an open file
is 01215). The generated input and output specifications of a display
format count its indicators (without `INDARA`) and its fields.

In a real interactive job the operations go to the job's display
(`work/qsjob/src/display/dds.rs`, the `DisplaySource` the 5250 session
shows); in the kit, to a scripted terminal (`PHASE9.md`).

An externally described printer file's formats come from its DDS
(`dds::prtf`): `WRITE fmt` moves the fields and option indicators into
the buffer and prints the format; at the overflow line the `OFLIND`
indicator goes on. In the real system `CRTBNDRPG` reads them from the
`*FILE PRTF` object `CRTPRTF` made (its compiled formats,
`lic/slic/src/cpp/rpg/source.rs`); at run time the job's printer open
(`prt_open` of `stg`) hands back the same object, and the job prints
each format through `spool::ddsprt` as the kit does.

**Printers.** A program-described printer without `OFLIND` gets the
first unused of `*INOA`-`*INOG` (`RNF2318`, information). A `WRITE` of
a structure to it prints one line and spaces one after; output records
print with their space and skip entries through `prtio ... ctl(sb, sa,
kb, ka)` (`QIR.md`), one line after when none is given.

## Dates, times and timestamps

A date, time or timestamp is held as IBM holds it: its characters in
the field's format (`03/05/26`, `14.30.05`, `2026-03-05-14.30.05.123456`),
`char(n)` in the IR. The IR's own `date`/`time`/`timestamp` types and
`dt.*` instructions are not used: they have no separators of the
programmer's choice, no century or long Julian forms, microseconds
only, and no RPG statuses. Format names (`*MDY-`, `*CYMD0`, `*HMS&`,
`*JOBRUN`) are parsed by `rpgc::dtfmt` into a **format word**: the
format code in bits 0-7, the separator in bits 8-15 (0 for none), a
timestamp's fractional digits in bits 16-23. The lexer keeps a
separator before `)` with its special word (`*MDY-)`).

`codegen/dates.rs` renders what is known at compile time: literals
(`d'...'` and `t'...'` in the control specification's `DATFMT` and
`TIMFMT`, `*ISO` by default; a timestamp literal is always `*ISO`, its
precision its fractional digits), `*LOVAL`/`*HIVAL` and the defaults
in the field's format (`*LOVAL` of a two-digit-year format is
1940-01-01, `*HIVAL` 2039-12-31; a time's `*HIVAL` is 24.00.00, which
`*USA` writes `12:00 AM`, its midnight being `00:00 AM`). The result of
date or time arithmetic, `%MAX` and `%MIN` is `*ISO`, whatever the
operands' formats.
Everything else calls `qrpgrt` with each operand's address, descriptor
and format word; for a character or numeric operand the format word
says how to read or write it. A duration (`%DAYS(n)`) is an `i64`
register of type `Ty::Dur`; `+`/`-` with a date and a duration, `%DIFF`
and `%SUBDT` (and `ADDDUR`, `SUBDUR`, `EXTRCT`) go to the runtime.
`DATFMT`/`TIMFMT` on the control specification set the default of
fields and of `%DATE`/`%TIME`/`TEST` on character and numeric data.
QS/400 has no job date format yet: `*JOBRUN` is `*MDY/` and `*HMS:`,
and `TIME` into a 12- or 14-digit field appends the date as `*MDY`.

| Procedure | Does |
|---|---|
| `_QRNX_DTCVT` | assignment between formats, `%DATE`, `%TIME`, `%TIMESTAMP`, `%CHAR`, `%DEC` |
| `_QRNX_DTCMP` | comparison by value (a date against a timestamp is its midnight) |
| `_QRNX_DTADD` | date arithmetic, `ADDDUR`, `SUBDUR`: months and years keep the day or cut it to the month's end |
| `_QRNX_DTDIFF` | `%DIFF`, `SUBDUR`'s difference form: whole units, the rest below the unit decides |
| `_QRNX_DTSUB` | `%SUBDT`, `EXTRCT` |
| `_QRNX_DTTEST` | `TEST` |
| `_QRNX_DTNOW` | `%DATE()`, `INZ(*SYS)`, `INZ(*JOB)`, `TIME` |

Values are days since 0001-01-01, seconds and picoseconds
(`qrpgrt::dates`); a failure signals `RNX0112` (not a valid value),
`RNX0113` (arithmetic outside 0001-01-01 to 9999-12-31) or `RNX0114`
(a year the target's format cannot hold), status 112, 113, 114.

## The runtime library (`qrpgrt`)

Procedures generated code binds to by name; the binder resolves any
`_QRNX_` import as a system import (`ile::binder::RPG_RUNTIME_PREFIX`)
and `qrpgrt::install` puts them into a job. Storage operands are
passed as addresses (`bytes *VARSIZE` parameters, which take any
type) with a descriptor word: the kind in the top byte (1 char, 2
varying, 3 packed, 4 zoned, 5 binary, 6 integer, 7 unsigned, 8
indicator, 9 date, 10 time, 11 timestamp, 12 float), the length or
digits from bit 8, decimals in the low byte.

**Moves** (`qrpgrt::mov`). Every operand takes part as its image:
character data as its bytes (a varying field as its current value, its
length unchanged), an indicator as its character, a number as its
zoned digits with the sign in the last zone. `MOVE` copies the image
right-aligned and `MOVEL` left-aligned; a numeric target then takes the
digit half of every byte (a digit above 9 is `MCH1202`) and the sign of
its last zone (`B`, `D` minus), and `MOVEL` into a number that factor 2
fills or overfills takes factor 2's sign. `MOVEA` works on the images
of the elements from the one named to the end of each array.

**Tables, occurrences, `RESET`.** A table named alone is its current
element (`$tix_NAME`, moved by `LOOKUP` and `%TLOOKUP`). A
multiple-occurrence structure is its current occurrence in its own
storage, every occurrence in `$NAME__occ` and the current number in
`$NAME__cur`; `OCCUR` saves the current one and fetches the next.
`RESET` restores a copy (`$NAME__rst`) that `_qrni_snap` takes when
initialization and `*INZSR` are done. A `DIM(*AUTO)` or `DIM(*VAR)`
array keeps its count in `$NAME__elem`.

**XML** (`qrpgrt::xml`). One parser gives `XML-SAX`'s events in
order and the element tree `XML-INTO` matches. `XML-INTO` gets its
target as a shape the compiler writes (`codegen::xml`: per node the
RPG name, the descriptor word, offset, elements and element size): the
root (or the elements `path=` names) must have the target's name under
`case=`, every subfield must be there (`allowmissing=yes` aside) and
nothing else (`allowextra=yes` aside); values are trimmed (`trim=all`:
the ends dropped, inner runs one blank). The number of elements set
goes to PSDS positions 372-379. A `%HANDLER` gets the elements in
groups of its array's size; an `XML-SAX` handler gets each event with
the string as a pointer (length -1 when the event has none). An error
in a handler is the operation's error. The special words
`*XML_START_DOCUMENT`... are integer constants (`codegen::xml::WORDS`).

## Status data structures

The positions the runtime keeps current, from 1, with the special word
that names a subfield there. `tools/conformance/tests/rpg_layouts.rs`
compares these tables with `mi::io::infds`, `qrpgrt::exc::PSDS` and the
compiler's special words (`rpgc::extfiles::INFDS_WORDS`, `PSDS_WORDS`).

## Embedded SQL (`CRTSQLRPGI`)

**The precompiler runs inside the compile.** IBM's precompiler writes
a second member (`QTEMP/QSQLTxxxxx`) with the SQLCA, a structure per
statement and calls to `QSQROUTE`, and compiles that. QS/400's
compiler already knows every host variable's type, so `rpgsqlpre`
works on the statements the front end keeps (an `EXEC SQL` operation
whose text holds one line break per source line) and hands `rpgc` one
`Stmt` per statement; the source keeps its own line numbers. For the
listing and its diagnostics to number lines as the oracle's does,
`rpgsqlpre::lines` counts what IBM's generated member adds: the
SQLCA, prototypes and constants (65 lines) and each main-source
statement's structure before the first calculation, each procedure's
structures before its first calculation, and after each statement
its call code (and three lines per active `WHENEVER ... GO TO`).

**The precompiler** (`rpg/sqlpre`): each statement is classified by
its first words. `SELECT ... INTO`, `VALUES ... INTO` and `SET :hv =`
are a query of at most one row (`INTO` lists taken out, `SET` made a
`VALUES`); `DECLARE CURSOR` is kept until its `OPEN`, which carries
the query, `WITH HOLD`, `SCROLL` and the declaration's host variables
(read when the cursor opens); `FETCH` keeps its orientation and `FOR n
ROWS`; `PREPARE`, `EXECUTE [USING]`, `EXECUTE IMMEDIATE` and `GET
DIAGNOSTICS` have their own kinds; `SET OPTION` (first statement only,
`SQL5066` per option), `WHENEVER`, `INCLUDE` and `DECLARE ... STATEMENT`
act at compile time; anything else runs as it is. Input host
variables become `?` (a structure one per subfield); `:v :i`, `:v:i`
and `:v INDICATOR :i` give indicators. The engine's text is parsed
(`SQL0104`); host variables must be known (`SQL0312`), cursors declared
before use (`SQL0504`), tables found (`SQL1103`, severity 10: the
program is still created); `UPDATE` and `DELETE` without `WHERE` are
`SQL0088` (00). Above `GENLVL` the command ends with `SQL9001` and
nothing is compiled. The precompile listing comes first in the
listing, with IBM's `DIAGNOSTIC MESSAGES` layout. `SET OPTION
CLOSQLCSR` takes `*ENDACTGRP` or `*ENDMOD` only (`SQL0104`).

**`INCLUDE`.** The front end's reader takes `EXEC SQL INCLUDE name`
(one free-form line, or `C/EXEC SQL INCLUDE name` and its
`C/END-EXEC`) like a `/COPY` of the member from the main member's
source file (`INCFILE(*SRCFILE)`); the statement reads as a comment
and the member's records follow it (`rpgfront::reader::SqlInclude`).
A member not found reaches the precompiler, which reports `SQL0004`.
For the listing's numbering an include before the first calculation
takes the main source's generated declarations, and a member that is
not fully free in a `**FREE` source counts IBM's `**END-FREE` and
`**FREE` lines. `INCLUDE SQLCA` does nothing more (the SQLCA is always
declared); `INCLUDE SQLDA` declares IBM's `SQLDA` (`SQLDAID`,
`SQLDABC`, `SQLN`, `SQLD`, `SQL_VAR` of 80 bytes `DIM(SQL_NUM)`, the
program's constant) and `SQLVAR` (`SQLTYPE`, `SQLLEN`, `SQLRES`,
`SQLDATA`, `SQLIND`, `SQLNAMELEN`, `SQLNAME`).

**Descriptors.** `DESCRIBE [INPUT] s INTO :da`, `PREPARE s INTO :da
FROM ...`, and `USING DESCRIPTOR :da` on `EXECUTE`, `OPEN` and `FETCH`
name the SQLDA with `_QRNX_SQLDA` before the statement runs: its
entries' `SQLDATA` and `SQLIND` pointers are read as the inputs or the
outputs (by `SQLTYPE` and `SQLLEN`, `SQLD` entries), or the
`DESCRIBE`'s reply fills it: `SQLDAID`, `SQLDABC` (`16 + 80 * SQLN`),
`SQLD`, and the entries when `SQLN` has room. `sql::embed::describe`
types a prepared statement without running it: columns from the
tables' formats, expressions by DB2's rules (integers, decimal
precision, `COUNT`), markers from what they are compared with or
assigned to, null-capable; a statement that is not a query has no
entries.

**Cursors' lifetime.** A statement's scope at run time is
`group:module`, the activation group's number and the module. When a
group ends (a `*NEW` group's program returns, `RCLACTGRP`) `mi::Job`
ends every scope of it (`Op::End` of `N:`), so its cursors close and
its prepared statements go (`CLOSQLCSR(*ENDACTGRP)`); under
`CLOSQLCSR(*ENDMOD)` the program entry calls `_qrni_sqlend` as it
returns, which ends the module's scope.

**The SQLCA** is declared as IBM declares it (`SQLCODE`/`SQLCOD`,
`SQLSTATE`/`SQLSTT`, `SQLERRD`/`SQLER1`-`6`, `SQLWARN`/`SQLWN0`-`A`,
`SQLERRMC`, ...; 136 bytes).

**Generated code** (`codegen/sql.rs`): `_QRNX_SQLIN` for each input
(address, descriptor word, date/time format, indicator),
`_QRNX_SQLOUT` for each output (and the element size of an array of
structures for a multiple-row `FETCH`), then `_QRNX_SQLRUN` with the
SQLCA, the statement's descriptor (`sql::embed::Desc`, text) and the
module name as the scope; then the `WHENEVER` branches.

**At run time** (`qrpgrt::sql`, `sql::embed`): the inputs become SQL
values, the job's `Embedded` (`mi::Job::sql`) runs the statement and
the row is assigned: a null into an indicator (-1, the variable
emptied) or `-305`; character data cut sets `SQLWARN1` and `01004` and
the indicator to the length; a number that does not fit is `-304` and
nothing is assigned; a failed statement assigns nothing except `-811`,
which gives the first row. `sql::embed::Session` runs over a store
(the kit's, or in a job the storage service's, through the `SqlRun`
request of `stg`): cursors and prepared statements per scope,
`-501`/`-502`/`-507` for cursor states, `-518` for an unprepared
statement, `-7007` for `COMMIT`/`ROLLBACK` without commitment
control, `01003` when a column function left out nulls, multiple-row
`FETCH` with `SQLERRD(5)` 100 at the last row.

## Adding a feature

1. Write corpus members that exercise it under
   `tools/conformance/rpg/<batch>/` (or a generator in
   `tools/conformance/rpg/gen/`); members print with a program-described
   `QSYSPRT`, one statement per line, at most 100 characters a line.
2. Run them on the oracle: `cargo run -p rpg-oracle -- run FILES` (or
   `refresh DIR --missing`); the outcomes land in `expected/`.
3. Implement until `cargo test -p conformance --test rpg_kit` matches
   (`QS400_RPG_ONLY=PREFIX` runs only the members whose names start
   so); our outcomes, listings and IR (with each diagnostic's text) are
   in `target/conformance-rpg/ours/`.
3. Implement until `cargo test -p conformance --test rpg_kit` matches;
   our outcomes, listings and IR (with each diagnostic's text) are in
   `target/conformance-rpg/ours/`. `cargo test -p conformance --test
   rpg_listing` compares the listings with IBM's (`docs/PHASE9.md`);
   the normalized pair is in `target/conformance-rpg/lst/`.
4. Keep clippy clean and commit.
