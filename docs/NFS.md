# NFS: the server and the client

Crates `net/xdrgen` (the XDR description compiler), `net/nfs` (ONC RPC,
the binder, MOUNT, NFS versions 3, 4.0 and 4.1, NLM, NSM, the export
table, the server and the client) and `tools/nfstest` (the test client).
`EXPORTFS` publishes IFS directories to NFS clients and `MOUNT
TYPE(*NFS)` mounts a remote export into the IFS, with IBM's commands,
daemon jobs and `/etc/exports`. Target release V1R2M0.

This document is the contract between the parts. Sections marked
**(design)** are decided and not yet built; the acceptance table at the
end says what is built and proven.

## 1. What the oracles settled

`tools/conformance/oracle/nfs/README.md` has the captures. In short:

- NFS is installed on both oracles and runs on neither; starting it is a
  configuration change this project does not make there. The commands,
  prompts, menus, message IDs, objects, daemon programs, `/etc` files and
  the two APIs come from the oracles and are followed exactly. The wire
  is built from the RFCs (5531, 4506, 1833, 1813, 7530, 7531, 8881,
  5662, and the Open Group's XNFS for NLM and NSM); every wire behaviour
  against a client or server that is not QS/400 is `NEEDS-CODY`
  (section 12).
- Things the handoff guessed that IBM does not have, and QS/400
  therefore does not add: `STRNFSSVR RETRY()`, `CHGNFSA`, `WRKNFSEXP`,
  `/etc/rpcbind`, `/etc/fstab`, `QIBM_QSTRTNFS`, a `QSYS2` NFS service.
  IBM has, and QS/400 adds, `STRNFSSVR RTVRPCREG()` and `SERVER(*GSS)`
  (refused, section 10), `RPCBIND`, `ENDRPCBIND`, `/etc/RPCBTAB`,
  `/etc/STATD`, `/etc/netconfig`, `/etc/vfs`, and the APIs `QZNFRTVE` and
  `QZNFNFSO`.
- `QSYS2.NFS_EXPORT_INFO` and `QSYS2.MOUNTED_FS_INFO` are QS/400's own
  (a documented difference): no release of IBM i has an SQL view of
  either.
- IBM starts NFS from the startup program or by hand. QS/400 does the
  same: nothing starts NFS at IPL unless `QSTRUP` is changed; exports
  made by `EXPORTFS` without `-A` last until the next IPL, as do mounts.

## 3. XDR and RPC

- Every protocol type is generated from `net/nfs/x/` by `net/xdrgen` in
  `net/nfs/build.rs`. No call's arguments or results are encoded by
  hand; hand-written code exists only in `src/xdr/` (the primitives) and
  where a protocol leaves the description (`nfs4.x`'s `bitmap4` and
  `fattr4` attribute values, which are opaque in XDR and get their own
  table-driven codec in `v4/attr/`).
- Decoding never trusts a length: each is checked against the
  description's bound (on encode too) and the bytes left, before
  anything is allocated; arrays check the count against the element's
  smallest encoding. Padding must be zero, a bool 0 or 1, an enum value
  or a union discriminant one the description has (`Error::Discriminant`
  names the type). Structs and unions count their depth (64 by default).
  Linked lists are decoded in a loop.
- Record marking: fragments are joined up to `record::MAX_RECORD` (1 MiB
  and 16 KiB); a larger record is an error and the connection is
  closed. A UDP datagram is one message.
- `AUTH_NONE` and `AUTH_SYS` (16 GIDs, a 255-byte name) are accepted with
  an `AUTH_NONE` verifier. Any other flavor, `RPCSEC_GSS` (6) included,
  and a malformed `AUTH_SYS` body are `MSG_DENIED`/`AUTH_ERROR` with
  `AUTH_BADCRED`; another verifier is `AUTH_BADVERF`. An RPC version
  other than 2 is `RPC_MISMATCH` 2 to 2. NFSv4 `SECINFO` and
  `SECINFO_NO_NAME` answer `AUTH_SYS` only.
- The duplicate request cache keys on (client address, port, XID,
  program, version, procedure) and keeps, for 60 seconds and up to a
  bound of entries, the replies of the procedures its caller names
  (`drc::NFS3_NONIDEMPOTENT`; NLM's). A retransmission gets the kept
  reply; one that arrives while the first runs gets none.
- Programs: `100000` (the binder, versions 2, 3, 4), `100003` (NFS,
  versions 3 and 4), `100005` (MOUNT, versions 1 and 3; version 1 only
  for `showmount`'s `DUMP` and `EXPORT`), `100021` (NLM, versions 1, 3
  and 4: 4 fully, 1 and 3 as the 32-bit forms of the same procedures),
  `100024` (NSM, version 1). A version outside a program's list is
  `PROG_MISMATCH` with the list's bounds; NFS version 2 is refused this
  way (IBM's V7R1M0 still registers it).

### 3.1 The generated code

`nfs::types::{rpc, rpcb, mount, nfs3, nlm, nsm, nfs4}`. Every name is
the description's, as the RFC writes it (`nfs_fh3`, `GETATTR3res`,
`nfsstat3::NFS3ERR_NOENT`); a Rust keyword is raw (`fattr3.r#type`,
`mon.r#priv`). What each definition becomes:

| XDR | Rust |
|---|---|
| `const X = n;` | `pub const X: u32` (`i32`, `i64`, `u64` when the value needs it) |
| `enum e { A = 1 }` | `enum e { A }` (`Copy`, `Eq`, `Hash`), `value()`, `from_value()` |
| `struct s { ... }` | `struct s` with the same fields |
| `union u switch (e d) { case A: T x; default: void; }` | `enum u { A(T), default(e) }`: a variant per label (`V5` for a literal 5, `TRUE`/`FALSE` for bool), `default` holding the discriminant and the arm; `discriminant()` |
| `union switch (bool) { case TRUE: T x; case FALSE: void; }` | `Option<T>` (`post_op_attr`, `set_mode3`, `newtime4`) |
| `typedef T x;`, `typedef opaque x[N];`, `typedef T *x;` | `pub type x = T;`, `[u8; N]`, `Option<T>` (`Option<Box<T>>` when `T` contains itself) |
| `typedef opaque x<N>;`, `string`, `T x<N>`, `T x[N]` | a newtype `pub struct x(pub Vec<..>)` checking the bound; `From`, and `AsRef<[u8]>` for bytes |
| inline `opaque x<N>`, `string x<N>`, `T x<N>`, `T x[N]` | `Vec<u8>`, `Vec<T>`, the bound checked by the codec |
| a list node: `struct s { ...; s *next; }` used only through `s *` | `s` without its link; `s *` is `Vec<s>` (`dirlist3.entries`, `mountlist`, `exports`, `pmaplist_ptr`) |
| `program P { version V { R PROC(A) = n; } = v; } = p;` | constants `P`, `V`, `PROC`; `mod P { NUMBER, VERSIONS, mod V { NUMBER, PROCEDURES, enum Args, enum Res } }` |

Every type implements `xdr::Xdr` (`MIN_SIZE`, `encode`, `decode`);
`xdr::to_bytes` and `xdr::from_bytes` (all bytes used) wrap them. A
version's `Args` and `Res` have one variant per procedure (a unit
variant for `void`) and implement `xdr::ProcBody`: `PROGRAM`,
`VERSION`, `procedure()`, `encode_body`, and `decode_body(procedure, d)`
(`Ok(None)` for a procedure the version lacks).

An NFSv4 operation number the description lacks fails `nfs_argop4`'s
decode with `Error::Discriminant { ty: "nfs_opnum4", .. }`: the v4
server decodes `COMPOUND4args`' header itself and answers `OP_ILLEGAL`
for that operation.

### 3.2 Writing a server program, calling a procedure

A program implements `rpc::Program`:

```rust
impl Program for Mount {
    fn program(&self) -> u32 { MOUNT_PROGRAM::NUMBER }
    fn versions(&self) -> &[u32] { &[1, 3] }
    fn call(&self, ctx: &CallContext, d: &mut Decoder<'_>) -> Answer {
        use MOUNT_PROGRAM::MOUNT_V3::{Args, Res};
        let res = match decode_args::<Args>(ctx, d)? {   // PROC_UNAVAIL, GARBAGE_ARGS
            Args::MOUNTPROC3_NULL => Res::MOUNTPROC3_NULL,
            Args::MOUNTPROC3_MNT(path) => Res::MOUNTPROC3_MNT(self.mnt(ctx, &path)),
            // ...every procedure
        };
        encode_res(&res)                                 // Ok(Some(bytes))
    }
}
```

`CallContext` has the caller's address and port, the transport, the
credential (`Credential::None` or `Credential::Sys(authsys_parms)`), the
XID, program, version and procedure. `Answer` is
`Result<Option<Vec<u8>>, AcceptError>`: `Ok(None)` sends no reply,
`Err` sends `PROC_UNAVAIL`, `GARBAGE_ARGS` or `SYSTEM_ERR`. A
`Dispatcher` holds the programs (`add`) and the cache (`set_cache`);
`Dispatcher::handle(bytes, peer, transport)` is the whole server as
bytes in and bytes out. A program whose state cannot cross
threads (a daemon thread's own file system) is an `rpc::LocalProgram`,
handed to `Dispatcher::handle_with(bytes, peer, transport, &[&p])`,
looked at before the dispatcher's own programs. `serve_tcp(&stream, &d, MAX_RECORD)` serves one
accepted connection, one call at a time with its replies in order (a
daemon runs a thread per connection); `serve_datagram(&sock, &d)` one
datagram.

A client:

```rust
let mut c = RpcClient::new(addr, Proto::Tcp, ClientConfig::default());
let cred = Credential::sys(b"host", uid, gid, &gids);
let res: Res = c.call_proc(&cred, &Args::MOUNTPROC3_MNT(dirpath(b"/home".to_vec())))?;
```

`call_raw(prog, vers, proc, cred, &args)` takes and gives bytes;
`call::<A, R>` any `Xdr` types. `ClientConfig` holds the per-attempt
`timeout`, UDP's `retransmits` and `max_timeout` (the timeout doubles to
it), `reserved_port` (1023 down to 512, else an ephemeral port without a
word), `max_record`, and `interrupt` (an `AtomicBool` that ends a wait
with `RpcError::Interrupted`). TCP connects on the first call and after
a failure; replies are matched by XID and others dropped; a call on a
kept connection that broke is sent once more on a new one. `RpcError`
tells `Timeout`, `Interrupted`, `Connect`, `ConnectionLost`, `Refused`
(an `AcceptError`, `mismatch()` for `PROG_MISMATCH`), `Denied`
(`RpcMismatch`, `Auth`), `TooLarge`, `Args`, `BadReply`.
`RpcClient::attempt(xid, &msg, timeout)` is one send and one wait, and
`is_retryable()` says whether resending the same XID is safe: `soft`
and `hard` are built on these by the NFS client, not in the transport.

### 3.3 The binder

`rpcb::Binder` is the `Program` for 100000. `SET` and `UNSET` are taken
only from a loopback address (FALSE otherwise, as rpcbind answers);
`UNSET` removes the caller's own registrations (by owner, the superuser
any). `GETPORT` and `GETADDR` answer the version asked or, as rpcbind
does, another version of the program on the netid; `GETVERSADDR` only
the version. `DUMP` (portmap: the `tcp` and `udp` entries), `GETTIME`,
`UADDR2TADDR`/`TADDR2UADDR` (Linux's `sockaddr_in`/`sockaddr_in6`),
`GETADDRLIST` and `GETSTAT` (calls per procedure, sets, unsets, lookups)
are answered. Remote calls (`CALLIT`, `BCAST`, `INDIRECT`) are refused
(section 10). Universal addresses are `h1.h2.h3.h4.p1.p2` and, as the
oracle writes them, `::.p1.p2`; netids `tcp`, `udp`, `tcp6`, `udp6`.
`Binder::on_change` is called with the table after every change, for
`QNFSRPCD` to write `/etc/RPCBTAB` (`rpcbtab::encode`, read back by
`rpcbtab::decode` for `RTVRPCREG(*YES)`). `BinderClient` does
`getport`, `getaddr` (version 4, else 3; a wildcard answer is made the
binder's host), `set`, `unset` and `dump`.

## 4. The daemons

As on the oracle (`tools/conformance/oracle/net/primary/dspsbsd-qsyswrk.txt`),
`QSYSWRK` has routing entries 2120 to 2127, each naming its program and
class in `QSYS` (`work/wm/src/obj/sbsd.rs`, added to an older system's
`QSYSWRK` once through `upgrade::ADDITIONS`, marker `QSYS/QP0LNFSD
*JOBD`). The job descriptions `QP0LNFSD` and `QP0LRPCD` are the
primary's (`oracle/nfs/jobd-primary.txt`: `USER(QUSER)`,
`JOBQ(QSYS/QSYSNOMAX)`, `JOBPTY(5)`, `RTGDTA` the compare value, `LOG(4 0
*NOLIST)`); the classes are the routing entries' eight, with
`QSYSCLS20`'s values (the primary's `QSYS` has `QP0LNFSD` and `QP0LRPCD`;
their attributes are `NEEDS-CODY`):

|---|---|---|---|---|---|---|
| 2123 | `QZNFRPCD` | `QNFSRPCD` | `QP0LRPCD` | `*RPC` | 111 tcp, udp | the binder |
| 2121 | `QZNFBIOD` | `QNFSBIOD` (`NBRBIO`) | `QP0LBIOD` | `*BIO` | none | the client's read-ahead and write-behind (section 7) |
| 2127 | `QZNFRGYD` | `QNFSRGYD` | `QP0LRGYD` | `*RGY` | none | the v4 identity mapping |
| 2120 | `QZNFNFSD` | `QNFSNFSD` (`NBRSVR`) | `QP0LNFSD` | `*SVR` | 2049 tcp, udp | NFS 3, 4.0, 4.1 |
| 2122 | `QZNFMNTD` | `QNFSMNTD` | `QP0LMNTD` | `*MNT` | any, registered | MOUNT |
| 2125 | `QZNFNSMD` | `QNFSNSMD` | `QP0LSTATD` | `*NSM` | any, registered | the status monitor, `/etc/STATD` |
| 2124 | `QZNFNLMD` | `QNFSNLMD` | `QP0LLCKD` | `*NLM` | any, registered | the lock manager |
| 2126 | `QZNFGSSD` | `QNFSGSSD` | `QP0LGSSD` | `*GSS` | | refused (section 10) |

**The registry.** The storage service keeps the daemon jobs
(`lic/slic/src/stgsvc/nfs/registry.rs`) and answers `stg::nfs` (tag
1540): `Start { daemon, count, rtvrpcreg }` submits the jobs of a type
that are not running (`count` for `*SVR` and `*BIO`, one for the others;
a count of 0 only asks how many run or wait on the queue) to
`QSYSNOMAX` with the type's job description and routing data, under
`QSECOFR` (NEEDS-CODY: IBM's user, section 12), as the service's own
request; `End { daemon }` marks every job of the type ending (one still
on the queue is told to end when it says hello). A job forgotten by the
job table (ended, crashed) leaves the registry at the next request.
Both need `*IOSYSCFG` (`CPFA1B8`).

**A daemon job** (`work/qsjob/src/work/nfs/`, `batch.rs` routes the
eight programs there) runs `lifecycle`: `Hello { daemon }` (refused to a
job not named as the type's), its type's `serve` (one module each:
`rpcd`, `biod`, `rgyd`, `nfsd`, `mntd`, `nsmd`, `nlmd`), `Ready { ports
}` with what it registered with the binder, then a wait of half a
second at a time until `ShouldEnd`, `ENDJOB` or its subsystem's end,
`Gone`, and `CPCA1B2` in its log. Today every `serve` is the one
`BLOCKED(rel)` hook of its daemon: it answers that it cannot serve, so
the job logs `CPI9C11` and `CPFA1BC`, leaves the registry and ends with
code 20 without ever reporting ready. Nothing claims to serve. The
lifecycle is tested with a serve that serves (`work::nfs::tests`).

**The commands** (`work/qsjob/src/command/nfs.rs`, in the job).
`STRNFSSVR SERVER(*ALL)` asks for each type in IBM's order: `*RPC`,
`*BIO`, `*RGY`, `*SVR`, `*MNT`, `*NSM`, `*NLM`; a single `*SVR`,
`*MNT`, `*NSM` or `*NLM` starts the binder first when it is not ready,
without a message of its own. For each type the command waits, a
quarter second at a time, until the registry has as many jobs of it
ready as asked: `CPIA1BB` when they are; `CPDA1BA` (`CPDA1BD` for each
of several) when they ran already; `CPFA1B9` when `STRJOBTIMO` passes
(`*NOMAX` waits for ever); `CPFA1BC` when the jobs are gone without
reporting ready (none registered or queued a second and a half after
the start). `CPCA1BB` ends it. `ENDNFSSVR` goes the other way,
`*NLM` to `*RPC`, ending each type running and waiting `ENDJOBTIMO` for
its jobs to leave the registry: `CPIA1BC` each, `CPFA1BD` at the
time-out, `CPCA1BC` at the end. `RPCBIND` is the binder alone
(`CPCA1B4` started, `CPCA1B6` running already, `CPFA1C9` not started
within 30 seconds), `ENDRPCBIND` its end (`CPCA1B5`, `CPFA1CA`).
`SERVER(*GSS)` logs `CPI9C10` and ends with `CPFA1BC` (`CPFA1BE` for
`ENDNFSSVR`); `*ALL` leaves it out.

**Several `QNFSNFSD` jobs.** The first job owns the listeners. It
serves UDP itself and gives each TCP connection to the job chosen by
the client's address (`sockets::relay::give`), so one client's NFSv4
state is in one job. What several clients share is in the storage
service: share reservations (the opens' share modes), delegations (the
lease table NetServer uses: a read delegation is a read lease, and a
break is `CB_RECALL`) and byte-range locks. Each job is multithreaded:
one thread per connection, each with its own link to the service.
**(design)**

**Restart and grace.** The storage service keeps the server's boot
verifier and, in `/QIBM/UserData/OS400/NFS/`, the stable-storage records
RFC 7530 section 9.6.3 asks for (client IDs with confirmed state). A
`QNFSNFSD` start after an end, a crash or an IPL begins a 90-second
grace period in which only reclaims are accepted (`NFS4ERR_GRACE`,
`NLM4_DENIED_GRACE_PERIOD`); NSM's state number in `/etc/STATD` goes up
by two and `QNFSNSMD` sends `SM_NOTIFY` to the hosts it monitored.
**(design)**

The loops each daemon job runs (register, serve, unregister) are
`nfs::server::run` (section 5.9); the jobs, their sockets and their
links are the job agent's.
## 5. The server over the IFS

Built in `net/nfs/src/server/` (shared by every protocol), `v3/`,
`mount/`, `nlm/`, `nsm/`; no job, store or service code. NFSv4
(`v4/`) is the next agent's and builds on the same `server` module
(section 5.9).

### 5.1 `Vfs`, `Req`, `VfsError`

`server::Vfs` is what the protocols ask of a file system. Every call
names a `Req` and handles:

```rust
pub struct Req { pub caller: Caller, pub export: Arc<dyn ExportView>, pub peer: IpAddr, pub opts: HostOpts }

pub trait Vfs {
    fn root(&self, r: &Req) -> VResult<Node>;
    fn lookup_path(&self, r: &Req, path: &[u8]) -> VResult<Node>;            // MOUNT
    fn getattr(&self, r: &Req, fh: &FileHandle) -> VResult<Attr>;
    fn setattr(&self, r: &Req, fh: &FileHandle, a: &SetAttr, guard: Option<Time>) -> VResult<Wcc>;
    fn lookup(&self, r: &Req, dir: &FileHandle, name: &[u8]) -> VResult<(Node, Option<Attr>)>;
    fn access(&self, r: &Req, fh: &FileHandle, want: u32) -> VResult<(u32, Option<Attr>)>; // ACCESS3_* bits
    fn readlink(&self, r: &Req, fh: &FileHandle) -> VResult<(Vec<u8>, Option<Attr>)>;
    fn read(&self, r: &Req, fh: &FileHandle, off: u64, count: u32) -> VResult<ReadData>;
    fn write(&self, r: &Req, fh: &FileHandle, off: u64, data: &[u8], stable: Stable) -> VResult<Written>;
    fn commit(&self, r: &Req, fh: &FileHandle, off: u64, count: u32) -> VResult<([u8; 8], Wcc)>;
    fn create(&self, r: &Req, dir: &FileHandle, name: &[u8], how: CreateHow) -> VResult<Made>;
    fn mkdir(&self, r: &Req, dir: &FileHandle, name: &[u8], a: &SetAttr) -> VResult<Made>;
    fn symlink(&self, r: &Req, dir: &FileHandle, name: &[u8], target: &[u8], a: &SetAttr) -> VResult<Made>;
    fn mknod(&self, r: &Req, dir: &FileHandle, name: &[u8], what: Special, a: &SetAttr) -> VResult<Made>;
    fn remove(&self, r: &Req, dir: &FileHandle, name: &[u8]) -> VResult<Wcc>;
    fn rmdir(&self, r: &Req, dir: &FileHandle, name: &[u8]) -> VResult<Wcc>;
    fn rename(&self, r: &Req, from: &FileHandle, from_name: &[u8], to: &FileHandle, to_name: &[u8]) -> VResult<(Wcc, Wcc)>;
    fn link(&self, r: &Req, fh: &FileHandle, dir: &FileHandle, name: &[u8]) -> VResult<(Option<Attr>, Wcc)>;
    fn readdir(&self, r: &Req, dir: &FileHandle, cookie: u64, verf: [u8; 8], max: usize, plus: bool) -> VResult<DirPage>;
    fn fsstat(&self, r: &Req, fh: &FileHandle) -> VResult<(FsStat, Option<Attr>)>;
    fn pathconf(&self, r: &Req, fh: &FileHandle) -> VResult<(PathConf, Option<Attr>)>;
    fn open(&self, r: &Req, fh: &FileHandle, access: ShareAccess, deny: ShareDeny) -> VResult<u64>;
    fn close(&self, open: u64) -> VResult<()>;
    fn lock(&self, r: &Req, fh: &FileHandle, sub: u64, kind: LockKind, start: u64, len: u64, wait: bool) -> VResult<LockOutcome>;
    fn test_lock(&self, r: &Req, fh: &FileHandle, sub: u64, kind: LockKind, start: u64, len: u64) -> VResult<Option<Conflict>>;
    fn unlock(&self, r: &Req, fh: &FileHandle, sub: u64, start: u64, len: u64) -> VResult<()>;
    fn cancel_wait(&self, token: u64) -> VResult<bool>;
    fn release_sub(&self, sub: u64) -> VResult<u32>;
    fn lease(&self, r: &Req, fh: &FileHandle, tag: u64, key: [u8; 32], want: u8) -> VResult<u8>;
    fn lease_report(&self, tag: u64, leases: &[([u8; 32], u8)]) -> VResult<()>;
}
```

Names and paths cross it as the client's bytes in the host's path name
CCSID, data as the client's bytes. `Attr` carries the protocol-neutral
attributes (type, mode, links, UID, GID, size, used, rdev, `fsid` =
export ID << 32 | file system, `fileid`, the three times, the change
counter, owner and group profile names, the CCSID). `LockOutcome` is
`Granted`, `Denied(Conflict)` or `Queued(token)`; `Conflict` names the
holder's job and sub-owner. `VfsError` is one list (`Perm`, `NoEnt`,
`Acces`, `Stale`, `BadHandle`, `NotSync`, `BadCookie`, `TooSmall`,
`Busy` for a share reservation, `Again` for a lock, `Deadlock`, ...)
with `From<Errno>`; each protocol maps it (`v3::conv::status`,
`nlm::status_of`). `server::news::NewsSource` is the poll for granted
lock tokens and lease breaks (`ClientNews` over any `IfsClient`).

### 5.2 `IfsVfs`

`server::ifsvfs::IfsVfs<C: IfsClient>` is the `Vfs` over the daemon
job's client (tests: `LocalIfs<MemBackend>`; the job: its link). A
daemon thread has its own (the client is not `Send`); what threads
share is in `Arc`s (exports, the duplicate request cache, the start's
`Instance`, the NLM and NSM tables). The job's umask is set to 0 when
one is made (the client applied its own).

- Each call runs as `as_caller(&req.caller)`; `ENOTENROLL` (from
  `as_caller` or from any call) runs it once more as the export's
  anonymous user (`cred::fallback`), or is `Acces` with `ANON=-1`.
- A handle is found with `stat_by_id` as the caller; `ESTALE`,
  `EBADFID` and `ENOENT` are `Stale` (and drop the object's kept
  descriptors). The path found must lie under the export's root (whose
  path the job resolves by the root's file ID and keeps), else
  `BadHandle`. `..` of the export's root is the root.
- Reads and writes go through a bounded cache of descriptors keyed by
  (file ID, caller, read or write), 64 kept, each closed after 5
  seconds unused, dropped when the object is removed, renamed over or
  found stale. Authority is checked when it is opened and again on
  every `READ` and `WRITE` (`access()` as the caller). An `OPEN` that a
  share reservation refuses (`EBUSY`) closes this thread's kept
  descriptors of the object and tries once more.
- An open's number is its descriptor, the job's, so any thread of the
  job may close it (NLM `UNSHARE` on another connection).
- Byte-range locks are held by sub-owners through descriptors of the
  job (read locks on one opened for reading, write locks on one opened
  for writing): the caller needs only to reach the object, as a lock is
  advisory. Offsets past `i64::MAX` are clamped and a range ending past
  it runs to end of file. Blocking requests use `lock_wait`.

### 5.3 File handles

`server::handle::FileHandle`, 32 bytes, the same for NFSv3, NFSv4,
MOUNT version 1 and NLM: the format byte (1), the export ID (4), the
file ID (file system 4, object 8, generation 4), the export root's
object number (8), and the low 24 bits of FNV-1a over the first 29
bytes. All big-endian. The handle carries no secret. Every call passes
`server::gate::Gate`: a handle of another length, format or check is
`BadHandle`; an export ID no longer in the table, or an export now of
another directory (its root number differs), is `Stale` (so
`EXPORTFS -U` takes effect at once); a client address not in
`ACCESS=`, or an NFS version not in `VERS=`, is `Acces`. A second
handle of one call (`RENAME`, `LINK`) in another export is `XDev`.

### 5.4 What the server needs of an export

`server::export::ExportView` (the lead adapts NFS-2's export model to
it), `ExportTable` (`by_id`, `all`, `for_path`: the longest export
holding a path, by whole components, without regard to case outside
`/QOpenSys`), and `MemExport`/`MemExports` with hosts as addresses and
networks (`HostPat`):

```rust

    fn writable(&self, peer: IpAddr) -> bool;      // not RO, in RW= if given
```

### 5.5 Attributes and changes

- `stat` to `fattr3`: the type from the mode's type bits (a `/QSYS.LIB`
  object that is neither a directory nor a file is a regular file),
  `mode & 0o7777` as `stat` shows the authorities (a missing primary
  group's bits are 0), times to the nanosecond.
- `SETATTR`: mode by `chmod` (`lchown` and no `chmod` for a link),
  owner and group by `chown` with the unchanged one kept, size by
  `ftruncate` (`IsDir` on a directory), times by `utime` (one time set
  keeps the other; both server times set both to now). The guard
  compares the change time exactly (`NotSync`).
- With `NOSUID`, set-user-ID and set-group-ID bits are cleared on
  everything made and every mode set.
- Every change answers the directory's or file's attributes before and
  after (`wcc_data`); a failure answers what can still be found.
- An exclusive `CREATE` keeps its verifier in the new file's times
  (access time the first four bytes as seconds, modification time the
  last four): a retransmission after the duplicate request cache
  forgot it, or after a restart, finds the file; another verifier is
  `EXIST`. The client sets the real times next.
- `MKNOD` makes FIFOs; sockets, character and block devices are
  `NFS3ERR_NOTSUPP`, another type `NFS3ERR_BADTYPE`.
- Names: empty, with `/` or NUL, or not valid in the host's path name
  CCSID: `INVAL`; over 255 bytes on the wire: `NAMETOOLONG`; `.` or
  `..` to make: `EXIST`.

### 5.6 Text conversion

As `NetServer` does it (`server::text`): with a data CCSID other than
`*BINARY`, a file tagged with a single-byte CCSID other than the host's
is converted byte for byte on read and write (sizes, offsets and locks
are the file's); a file in a multi-byte or mixed CCSID, 65535 or the
host's own is served as stored. A file made through the export is
tagged with the host's data CCSID (else the IFS's default). Path names
are converted between the host's path name CCSID (UTF-8 or a
single-byte CCSID; others `INVAL`) and the IFS's UTF-8.

### 5.7 NFS version 3

`v3::call(vfs, gate, ctx, d)` answers one call; `v3::Nfs3<V>` is the
`LocalProgram` of a thread serving version 3 alone. All 22 procedures.
`FSINFO`: `rtmax`/`wtmax` 1 MiB, `rtpref`/`wtpref`/`dtpref` 64 KiB,
multiples 4096, `maxfilesize` `i64::MAX`, `time_delta` 1 ns,
`LINK|SYMLINK|HOMOGENEOUS|CANSETTIME`. `PATHCONF`: `name_max` 255,
`no_trunc`, `chown_restricted`, case-insensitive per file system,
case-preserving. A change through an export the client may not write is
`NFS3ERR_ROFS`. `WRITE` with `count` above 1 MiB is `FBIG`, with less
data than `count` `INVAL`; `*SYNC` hosts get `FILE_SYNC`. The write
verifier is the `Instance`'s, new at every start. `READ` reports end of
file at the size or on a short read. `ACCESS` asks `access()` as the
caller for each bit (`LOOKUP` on directories, `EXECUTE` on files,
`DELETE` on directories only; none of the changing bits on a
read-only export). `JUKEBOX` is never answered.

`READDIR`/`READDIRPLUS`: from cookie 0 the page starts with `.`
(cookie 1) and `..` (cookie 2); then the file system's entries in
cookie order, a cookie being the entry's name hashed (FNV-1a, 62
bits, plus 3). So a cookie stays good while the directory changes: an
entry removed is not seen, one added may be, none is seen twice or
skipped; two names of one cookie stay on one page. The cookie
verifier is the directory's file ID hashed; a cookie with another
directory's verifier is `BAD_COOKIE` (a zero verifier is taken).
Pages are cut to `count` (`READDIR`), or to `dircount` bytes of names
and `maxcount` in all (`READDIRPLUS`), as XDR encodes them; a page
that holds no entry is `TOOSMALL`.

The duplicate request cache keeps `SETATTR`, `CREATE`, `MKDIR`,
`SYMLINK`, `MKNOD`, `REMOVE`, `RMDIR`, `RENAME`, `LINK`
(`server::run::nfs3_cache()`).

### 5.8 MOUNT, NLM, NSM

- **MOUNT** (`mount::Mountd<V>`, versions 1 and 3): `MNT` takes the
  export or a directory under it (longest export wins; the path in the
  host's path name CCSID); a path in no export, a host not allowed, or
  a caller who cannot reach it: `MNT3ERR_ACCES`; missing:
  `MNT3ERR_NOENT`; not a directory: `MNT3ERR_NOTDIR`; it answers the
  handle and `[AUTH_SYS]`. Version 1's `MNT` answers the same 32 bytes
  or the errno. The mount list (`mount::list::MountList`, the client's
  `AUTH_SYS` machine name or address and the IFS path) is kept in
  memory (`MemMountList`): the oracle has no `rmtab`-like file, so the
  list starts empty with each start of `QNFSMNTD`. `EXPORT` (and v1
  `EXPORTALL`) lists every export with its `groups()`.
- **NLM** (`nlm::Nlm<V>`, versions 1, 3, 4 and 2 = `NLM_SM`): section
  `nlm/mod.rs` has the rules. A lock owner (caller name without case,
  `svid`, owner handle) is an IFS sub-owner from `0x4E4C000000000000`
  up. Blocking: `NLM4_BLOCKED`, then `nlm::grant::grant_loop` (the
  daemon's poll) calls the client back with `NLM_GRANTED`
  (`GRANTED_MSG` if it asked with `LOCK_MSG`); a client that refuses it,
  or does not answer in `grant_tries`, has it given back. A request
  retransmitted while it waits is answered `BLOCKED` and queued once.
  `CANCEL`: `GRANTED` when taken back (a lock granted meanwhile is
  unlocked), `DENIED` when nothing waits. Grace period (90 s by
  default, `NlmConfig::grace`, on a `Clock`): `LOCK`, `NM_LOCK`, `SHARE`
  without reclaim and `TEST` are `NLM4_DENIED_GRACE_PERIOD`; `UNLOCK`
  and `CANCEL` are taken. The first lock of a host (not `NM_LOCK`)
  asks the local monitor `SM_MON` with `my_id` = (`127.0.0.1`, 100021,
  2, 1); a refusal is `NLM4_DENIED_NOLOCKS`. `NLM_SM_NOTIFY` (from this
  host only), `FREE_ALL` (from the host itself: its `AUTH_SYS` machine
  name or address is the name, or from this host) and
  `NlmState::release_client(vfs, name)` (`RLSIFSLCK RMTLOCNAME`) drop
  every lock, waiting request and share of a host. `SHARE`/`UNSHARE`
  are opens with share reservations. The `_MSG` forms are answered
  with no results and their `_RES` sent to the client's lock manager
  after the reply. `GRANTED` and the `_RES` messages a client would
  receive go to `NlmState::set_client` (the mounting client's, a later
  agent's); without one `GRANTED` is `DENIED` and those `_RES` are
  `PROC_UNAVAIL`. Version 1 and 3 statuses version 4 adds are sent as
  `nlm_denied_nolocks`. The duplicate request cache keeps procedures
  2, 3, 4, 7, 8, 9, 20 to 23 (`server::run::nlm_cache()`).
- **NSM** (`nsm::Nsm`, version 1): `SM_STAT` answers `stat_succ` and
  the state; `SM_MON`, `SM_UNMON`, `SM_UNMON_ALL` only from this host
  (elsewhere `stat_fail`, or the state with nothing changed);
  `SM_SIMU_CRASH` only from this host (`PROC_UNAVAIL` from another):
  the state up by two and every monitored host told; `SM_NOTIFY` from a
  host calls back each local program monitoring it (by name without
  case, or by the caller's address) with its private bytes. At a start
  (`NsmState::start`) the state goes to the next odd number (1 from
  none, +2 from odd, +1 from even), the hosts monitored before are
  handed back and forgotten, and `run::nsmd` tells each (`SM_NOTIFY`
  with this host's name, `notify_rounds` rounds). The files, through
  `nsm::record::StatdStore`: `/etc/STATD` (EBCDIC digits and `X'15'`,
  the oracle's form) and the monitored hosts,
  `/QIBM/UserData/OS400/NFS/QNFSNSMD.MON`, a format of this release:
  `QSMN`, version u16 1, two zero bytes, count u32, then per host
  `mon_name` and `my_name` (u16 length, at most 1024 bytes),
  `my_prog`, `my_vers`, `my_proc` (u32) and 16 private bytes;
  big-endian.
- Calls out go through `server::locate::Locator` (the client's NLM at
  its address, the local NSM at `127.0.0.1`, a monitored host's NSM by
  name): `BinderLocator` asks the host's port 111; tests use
  `FixedLocator`. The client calls are `nlm::call` and `nsm::call`.

### 5.9 The daemons' loops, and what NFSv4 shares

`server::run` (no global state; every thread scoped to the call):

```rust
pub struct Listeners { pub tcp: Option<TcpListener>, pub udp: Option<UdpSocket> }
pub struct Registration { pub binder: SocketAddr, pub owner: String }
pub struct Common<'a> { pub listeners: Listeners, pub binder: Option<Registration>,
                        pub stop: &'a AtomicBool, pub ready: Option<&'a (dyn Fn() + Sync)> }
pub fn nfsd<P: LocalProgram, F: Fn() -> P + Sync>(c: Common<'_>, make: F) -> io::Result<()>;
pub fn mountd<V: Vfs, F: Fn() -> V + Sync>(c: Common<'_>, exports: &Arc<dyn ExportTable>,
    list: &Arc<dyn MountList>, vfs: F) -> io::Result<()>;
pub fn nlmd<V: Vfs, F: Fn() -> V + Sync, N: Fn() -> Box<dyn NewsSource> + Sync>(c: Common<'_>,
    exports: &Arc<dyn ExportTable>, state: &Arc<NlmState>, vfs: F, news: N) -> io::Result<()>;
pub fn nsmd(c: Common<'_>, state: &Arc<NsmState>, before: Vec<MonRecord>) -> io::Result<()>;
pub fn serve<P, F>(c: Common<'_>, d: &Dispatcher, prog: u32, versions: &[u32], make: F,
    extra: Option<&(dyn Fn() + Sync)>) -> io::Result<()>;
```

Each registers its versions on its listeners' addresses with the binder
(an earlier registration unset first), calls `ready`, serves UDP on one
thread and each TCP connection on a thread with its own program from the
factory, and at `stop` lets the threads end and unregisters. `nlmd`
registers versions 1, 3 and 4 (not 2) and runs the grant poll and the
`_RES` sender beside; `nsmd` runs the notices of the start and the
callbacks. All links of one daemon job are one IFS owner: tokens queued
by one thread are named by the poll of another (for the job agent:
the service's owner of each link must be the job, not the link).

A thread's own program is a `rpc::LocalProgram` (the `Program` trait
without `Send`/`Sync`), handed to `Dispatcher::handle_with(msg, peer,
transport, &[&program])`. NFSv4 shares: `Vfs` (extend it only for what
is missing), `IfsVfs`, `FileHandle` (v4 handles are the same 32
bytes), `Gate` (call `open(ctx, fh, 4)`), `cred`, `text`, `Instance`
(the boot verifier), `Clock`, `NewsSource` (lease breaks for
`CB_RECALL`), `Locator`, and `run::nfsd` with a program of versions 3
and 4 that calls `v3::call` for version 3. Opens with share
reservations are `Vfs::open`/`close`; v4 lock owners need their own
sub-owner range (NLM's starts at `0x4E4C000000000000`).

### 5.10 `/QSYS.LIB` and NFSv4 **(design)**

- **`/QSYS.LIB`** exports show libraries, objects and members as
  directories and files (built and tested over `MemQsys`: `.FILE` a
  directory of `.MBR` files, a user space a file). `/QOPT` and `/QDLS`
  cannot be exported (`CPDA1C5`); nor can `/QNTC`, `/QFileSvr.400` or
  an NFS mount (the commands' agent).
- **NFSv4.** The pseudo-file system joins the exports under one root
  (read-only directories made of the exports' path components).
  Compound operations of 4.0 and 4.1; stateful opens with share
  reservations; byte-range locks; read delegations (write delegations
  are not offered); `SETCLIENTID` and callbacks for 4.0;
  `EXCHANGE_ID`, sessions, slots with exactly-once replies, the
  backchannel, `RECLAIM_COMPLETE`, `SEQUENCE` for 4.1. Referrals are
  refused (`fs_locations` is not a supported attribute), pNFS is refused
  (`EXCHGID4_FLAG_USE_NON_PNFS`, `LAYOUT*` and `GETDEVICE*` answer
  `NFS4ERR_NOTSUPP`). NFSv4 `owner`/`owner_group` are `profile@domain`
  through the registry, the domain from `QZNFNFSO`.

### 5.11 What the IFS gives the daemons

- **Identity per request** (built, `docs/IFS.md` "Calls as another
  user"). A daemon thread's calls name the caller:
  `IfsClient::as_caller(&Caller)` (over the link
  `RemoteIfs::as_user(Caller)`) answers a client whose every call is
  one request, `IfsOp::As` (72). `Caller` is `Uid { uid }`, `Profile {
  name }` or `Anonymous` (`QNFSANON`). The service honours it only for
  `QNFSNFSD`, `QNFSMNTD` and `QNFSNLMD` (`EPERM` for any other job). The
  UID maps to the user profile with that UID whatever its status;
  authority is that profile's, with its group profiles (the wire's GID
  list is never used). A UID no profile has answers `ENOTENROLL` on the
  call: the daemon then retries as the export's `ANON=` user
  (`Caller::Uid` of it, or `Caller::Anonymous` for the default) or, with
  `ANON=-1`, refuses (`NFS3ERR_ACCES`, `NFS4ERR_ACCESS`). Root squashing
  is the daemon's: UID 0 is `QSECOFR`, so the daemon sends `Uid { 0 }`
  only for a host in `ROOT=`. The service keeps the profiles by UID and
  the principals built until any profile, group or list changes.
  Descriptors opened as a user are the job's (the daemon's handle
  cache); authority is checked at open, so per-call checks (`ACCESS`, an
  NFSv3 `READ` or `WRITE` on a handle) are the daemon's, through
  `access()` as the user.
- **File handles** are 32 bytes: a format byte, the export's ID (4), the
  IFS `FileId` (file system 4, object 8, generation 4), the file ID of
  the export's root (8) and a checksum. The object number is xfs's and
  the generation xfs's inode generation (kept in the record's
  generation field), so the `FileId` is the xfs handle and a reused
  inode number never meets its old generation; objects from before
  this release keep generations from a counter whose high-water mark is
  on the volume (`trusted.qs400.gen`). `stat_by_id` (73) and
  `open_by_id` (74) take a `FileId` to its path and attributes, or to a
  descriptor and the path, in one request as the caller, without a
  walk: the service opens the xfs handle (`open_by_handle_at`,
  `ifs/fhandle`) and names it by its `/proc/self/fd` link. That needs
  no walk for a directory, nor for a file the kernel has a path for; a
  file not in its cache since the IPL (an xfs handle names no parent),
  or an object with an old generation, falls back to the paths the
  service remembers (65536) and then a walk of its file system that
  remembers what it passes (`docs/IFS.md`, "File IDs"). `/QSYS.LIB`
  resolves by the hashes of library, object and member, level by level,
  a collision refused (`EBADFID`). A handle whose
  object is gone, whose generation differs, or whose file system is no
  longer mounted (a UDFS mounted again gets a new number) is `ESTALE`:
  `NFS3ERR_STALE`/`NFS4ERR_STALE`; one outside its export
  `NFS3ERR_BADHANDLE`. A handle is checked against the export table on
  every call, so `EXPORTFS -U` takes effect at once. Objects with
  generation 0 (made before generations, `/QSYS.LIB`) are matched by 0.
- **Lock owners** (built). `lock_range_as(fd, sub, ...)` (75) holds a
  lock for a sub-owner within the job (a `u64` the daemon chooses per
  NLM (host, owner handle) or NFSv4 lock owner; 0 is the job itself), so
  they conflict with each other and with local jobs. A sub-owner's locks
  outlive the daemon's descriptors; `lock_release_sub(sub)` (78) drops
  them (NLM `FREE_ALL`, `SM_NOTIFY`, an NFSv4 lease expiry) and
  `owner_locks` lists them with their sub-owner (for `RLSIFSLCK` and
  `IFS_OBJECT_LOCK_INFO`). Blocking locks wait in the service:
  `lock_wait` (76) grants at once or answers a token, the daemon's
  `lease_orders` poll names each token once granted (`News::locks`;
  NLM answers `NLM_BLOCKED`, then sends `NLM_GRANTED`), `lock_cancel`
  (77) takes one back (`NLM_CANCEL`); a cycle of waits is `EDEADLK`
  (`NLM4_DEADLCK`). NFSv4 answers `NFS4ERR_DENIED` and the client
  polls. Share reservations are the opens' share modes, enforced
  between jobs; `QNFSNFSD` holds leases and watches as `QZLSFILE` does.

### 6.1 `/etc/exports`

One export a logical line (`nfs::exports::file`): `#` outside double
quotes starts a comment, a `\` that ends a line joins the next one.

```text
path [-option[,option]...] [HOSTOPT host[:data[:path[:write]]]]...
```

- `path` is absolute, in double quotes when it holds blanks or `#`;
  trailing slashes are dropped. Paths compare without case.
- The option list starts with `-` and runs to the first word `HOSTOPT`
  (any case); blanks after its commas are allowed, as IBM's examples
  write them. Its options are those of `EXPORTFS -O` below.
- Each `HOSTOPT` gives one host's options: the data CCSID (`*BINARY`,
  `*ASCII`, `*JOBCCSID` or a number), the path name CCSID (`*ASCII`,
  `*JOBCCSID` or a number), the write mode (`*SYNC`, `*ASYNC`); those
  left out take their defaults (`*BINARY`, `*ASCII`, `*SYNC`). At most
  ten.
- An IPv6 address goes in brackets, everywhere a host does: `[fd00::1]`,
  `@[fd00::]/64`.

NEEDS-CODY: IBM's own `HOSTOPT` form in `/etc/exports` and what its
`EXPORTFS -F` writes (the sequence in section 12); QS/400 reads and
writes the form above.

The export options (`nfs::exports::options`; an option given twice is

## 7. The client: an NFS mount in the IFS **(design)**

The storage service is one thread over one store and must never wait
for a network. A remote mount therefore works on a cache and never
blocks the serve loop:

- `ifs::remote::RemoteFs` is the trait a remote file system implements
  (blocking calls: `lookup`, `getattr`, `setattr`, `access`, `read`,
  `write`, `commit`, `create`, `mkdir`, `symlink`, `mknod`, `remove`,
  `rmdir`, `rename`, `link`, `readdir`, `readlink`, `statfs`,
  `pathconf`, `open`, `close`, `lock`). `nfs::client::Mount` is the
  implementation; tests use one in memory with delays and failures.
- `FsKind::Remote` is a mount whose nodes are remote handles. An IFS
  operation that reaches one answers from the mount's cache
  (attributes, names, directory pages, data blocks); on a miss, or for
  a change, it leaves a request in the mount's queue and a `Deferral`,
  exactly as an operation that waits for a lease break does. Worker
  threads of the service (one pool per mount, the "kernel" of the
  client) run the queued calls; when one finishes the parked request
  runs again and finds its answer. A change is queued once, under the
  request's token, and its second run takes the result.
- The attribute cache follows `acregmin`/`acregmax`/`acdirmin`/
  `acdirmax` (`noac` turns it off); data blocks of `rsize` are cached
  and validated by the file's change attribute or modification time;
  writes are cached to `wsize` blocks and sent `UNSTABLE` then
  `COMMIT`ted on `fsync` and close (`FILE_SYNC` with the export's
  synchronous option or without block I/O daemons). `QNFSBIOD` jobs,
  when started, take the read-ahead and write-behind work from the
  same queue; without them the service's threads do it at the request.
- `hard`: a call is retried for ever, `timeo` tenths of a second
  doubling to 60 seconds, a message to `QSYSOPR` when the server stops
  answering and when it answers again; the request stays parked and no
  other job is held. `intr`: ending the job, or System Request 2,
  takes the request back with `EINTR`. `soft`: after `retrans`
  retransmissions the call fails with `ETIMEDOUT`. `retry` is the
  number of times the mount itself is tried. `bg` is refused.
- `vers=3` (the default, as `/etc/vfs` says) or `vers=4` (`4.0`, `4.1`);
  `proto=tcp` or `udp` (v4 is TCP only); `rsize`, `wsize` up to 1 MiB;
  `sec=sys`; `rw`/`ro`; `suid`/`nosuid`; `port=`, `mountport=`.
  `CCSID`/`CODEPAGE` convert data and path names as the server's
  `HOSTOPT` does.
- The caller's credentials are `AUTH_SYS` with the job's user profile's
  UID, GID and group profiles' GIDs.
- Locks: `fcntl` byte-range locks on a remote file go to the server (NLM
  for version 3, with `QNFSNSMD` and `QNFSNLMD` running, else `ENOLCK`;
  `LOCK` for version 4) and are reclaimed after the server restarts.
- `UNMOUNT TYPE(*NFS)` refuses while anything is open or current in the
  mount; it flushes, tells the server's MOUNT daemon and ends the pool.
- Mounts last until the next IPL, as IBM's do. To have them back, put
  `MOUNT` in the startup program (`QSTRUP`).

## 9. Security mapping

The IFS side is built (`docs/IFS.md`, "Calls as another user"), and
the server's use of it (`server::cred`, `server::ifsvfs`; section 5.2).

| On the wire | On QS/400 |
|---|---|
| `AUTH_SYS` UID | the user profile with that UID, enabled or `*DISABLED` (IBM maps by UID; only sign-on checks the status: NEEDS-CODY, settled by mounting the primary's export as a UID whose profile is disabled); none: the anonymous user |
| UID 0 | `QSECOFR` for `ROOT=` hosts; else the anonymous user (root squash is the default, as IBM's) |
| GID list | not used for authority; the profile's group profiles are |
| `AUTH_NONE` | the anonymous user |
| the anonymous user | `ANON=uid` (default the UID of `QNFSANON`); `-1` refuses |
| mode bits | the data authorities of owner, primary group and `*PUBLIC`, as `stat` and `chmod` map them |
| a set-user-ID or set-group-ID bit | cleared on everything made, and every mode set, through an export with `NOSUID` |
| ports | calls from ports of 1024 and up are accepted (IBM's default); the client sends from a reserved port when it can |

Auditing follows the caller's profile: the `QAUDJRN` entries are those
the same change makes locally, charged to the mapped profile, with the
daemon job's name and number.

**UIDs.** QS/400's shipped profiles have IBM's UIDs (the primary's,
`tools/conformance/oracle/nfs/uids-primary.txt`): `QSECOFR` 0, `QSYS`
101, `QDFTOWN` 102, `QTMPLPD` 103, the others fixed numbers from
4294770688 up (`QPGMR` 4294770688, `QSYSOPR` 4294770689, `QUSER`
4294770692, `QNFSANON` 4294770710 ...); `QSOC` and `QUMB` have none.
No shipped profile has a GID. Generated UIDs and GIDs (`*GEN`) start at
100 (or `CHGSECA`'s start), stay below 4294770688 and skip numbers in
use. A UID or GID another profile has is refused (`CPF22CE`, `&1` the
keyword, `&2` the number), and `QSECOFR`'s UID cannot change
(`CPF224C`); both messages are IBM's IDs, found on the primary.

On a system installed before this, every shipped profile has UID 0 (no
number yet): the first IPL of this release gives each one IBM's UID
where no other profile already has that number. A profile that has a
UID keeps it (objects and clients may know it by it); `QSECOFR` is set
to 0 (only a `CHGUSRPRF QSECOFR` could have given it another, wrongly).
IFS objects record their owner by name, so no object changes owner;
the xfs mirrors of owner UIDs follow at the next `RCLLNK` or change. A
shipped profile whose number a user profile already holds stays
without a UID: NFS then maps nobody to it.
